# Архитектура Atlas

Цель — чтобы любую функцию можно было **добавить, изменить, отключить или удалить**, не трогая остальные.

## Слои

```
atlas/
  app.py                      # точка входа: конфиг → ядро → загрузка функций → главное окно
  selfcheck.py                # --selfcheck: вход и вкладки без человека, отчёт и снимки (CI, выезд)
  dbcheck.py                  # --dbcheck: SQLite на сетевом диске, обрыв сети, два ПК
  viewbench.py                # --viewbench: скорость просмотра фото, сетевой диск только читается
  publish.py                  # --publish: положить эту версию в папку установки на сетевом диске
  addfolder.py                # --addfolder: внести настоящую папку с фото в базу, пока нет импорта из письма (6.x)
  core/                       # ядро: ничего не знает о конкретных функциях
    app_context.py            # AppContext: config, db, bus, services, user, paths
    feature.py                # FeatureSpec, Feature (базовый класс)
    registry.py               # FeatureRegistry: читает config/features.json, импортирует, сортирует по зависимостям
    bus.py                    # EventBus: publish/subscribe (через Qt-сигналы, потокобезопасно)
    services.py               # ServiceRegistry: register/get/get_optional
    db.py                     # подключение SQLite, ретраи, MigrationRunner (миграции ядра + каждой функции)
    config.py                 # config/*.json + локальные настройки машины (config/local.json, не в git); AppPaths: root (файлы версии) и home (настройки, данные)
    release.py                # раскладка установки, version.txt, версия программы
    domain/                   # таблицы ядра (users, projects, devices, parts, folders, photos) и сервисы к ним;
                              # photo_names.py — разбор имени фото (артикул, ракурс, SN), шаблон в data/photo_names.json
    logging_setup.py          # журнал в logs/, сбор ошибок
    qt_runtime.py             # подготовка Qt до QApplication
    theme/                    # atlas.qss, tokens.json (цвета), иконки SVG
    shell/                    # главное окно: верхняя полоса, вкладки, строка контекста, слоты панелей
  shared/                     # переиспользуемое, без бизнес-логики
    viewer/                   # PhotoView, SyncGroup, ImageCache, Filmstrip
    annotate/                 # model (фигуры, History — отмена/повтор), paint, store (AnnotationStore), overlay (мышь и рисование поверх PhotoView)
    widgets/                  # NameTag, ContextBar, FlowLayout, LogoMark, icons (значки кнопок: Lucide, SVG в widgets/icons/ с файлом лицензии ISC; `set_icon(button, "имя", токен цвета)`), StampAnimation (stamp.py: кадры анимации «В АРХИВЕ»); Toast, SearchBox — по мере надобности
    outlook/                  # base.py, outlook_win.py, outlook_fake.py
    fs/                       # moves.py: безопасное перемещение (не перезаписывает, ошибки по файлам); photos.py: поиск .jpg/.jpeg в папке; дальше — копирование, блокировки
  features/
    <id>/
      __init__.py             # FEATURE = FeatureSpec(...)
      logic.py                # чистая логика — без Qt, тестируется отдельно
      repo.py                 # доступ к своим таблицам
      ui.py                   # виджеты/вкладка
      migrations/001_init.sql
      tests/
config/
  features.json               # какие функции включены и в каком порядке
  app.json                    # сетевые пути, режим fake/real, лимиты памяти
data/                         # справочники: defect_kinds.json, photo_names.json, placement_rules.json, hotkeys.json …
templates/                    # mail_reply.html, excel_columns.json
packaging/                    # atlas.spec, bundle_contents.py, version_info.txt, bat/ (проверки на выезде)
scripts/                      # check_pe_imports.py, assemble_dist.py
```

Новая функция попадает в сборку сама: `packaging/bundle_contents.py` обходит `atlas/`, берёт все модули и все файлы, кроме кода
(без `tests` и `_template`). Рядом с exe лежат `config/`, `data/`, `templates/`, их можно менять без пересборки.

## Контракт функции

```python
# atlas/features/rules/__init__.py
from atlas.core.feature import FeatureSpec
FEATURE = FeatureSpec(
    id="rules",
    title="Правила",
    version=1,
    requires=[],                     # жёсткие зависимости (другие функции) — по возможности пусто
    optional=["compare"],            # если есть — используем, если нет — работаем без них
    tab_order=40,                    # место вкладки; None — функция без вкладки
    factory="atlas.features.rules.ui:RulesFeature",
)
```

```python
class Feature:
    def __init__(self, ctx): ...          # AppContext
    def on_start(self): ...               # подписки на события, регистрация сервисов
    def create_tab(self): ...             # QWidget или None
    def badge(self): ...                  # счётчик/подсветка на вкладке или None
    def settings_page(self): ...          # страница в «Настройках» или None
    def on_stop(self): ...
```

Ядро загружает только функции из `config/features.json`. Отключённая функция **не импортируется**.

```json
{"features": [{"id": "rules", "enabled": true, "tab_order": 40}]}
```

`tab_order` в `features.json` необязателен и важнее значения в `FeatureSpec`. Запись без `tab_order` берёт значение из `FeatureSpec`.

Ошибка функции (импорт, зависимости, миграции, запуск) не роняет приложение: она пишется в журнал, в `registry.failures` и в событие `feature.failed`.

## БД из кода функции

```python
rows = ctx.db.read(lambda conn: conn.execute("SELECT ...").fetchall())
ctx.db.write(lambda conn: conn.execute("INSERT ...", (...)))
```

На каждый вызов — своё подключение, поэтому вызывать можно из любого потока (но не из GUI). При блокировке транзакция откатывается и функция вызывается заново, поэтому внутри неё — только работа с базой и никаких вложенных `read`/`write`. Если база занята дольше всех повторов — `DatabaseBusyError`.
Миграции применяются при старте: сначала ядра (`core/domain/migrations`, ошибка останавливает запуск), потом функций. Менять уже применённый файл нельзя (проверяется контрольная сумма).

## Правила связей
1. `features/X` импортирует только `atlas.core.*` и `atlas.shared.*`. Проверяет `tests/test_boundaries.py` (ast-разбор импортов).
2. Сообщить другим — `ctx.bus.publish("finding.added", {...})`. Что-то получить — `ctx.services.get_optional("type_db")`;
   если `None` — блок интерфейса скрывается, а не падает.
3. Функция встраивается в чужой экран только через **слоты** оболочки: `ctx.shell.add_panel("compare.right", widget)`.
   Например, сводка по детали — функция `findings` кладёт свою панель в слот `compare.right`.
4. Свои таблицы — только свои. Чужие данные — через сервис владельца. Таблицы ядра — через сервисы `users`, `parts`, `folders`; они есть всегда.
5. Всё, что меняется без программиста (списки, шаблоны, горячие клавиши), — в `data/` и `templates/`.

Правила (`rules`, 7.1): таблицы `rules`, `rule_photos`, `rule_reads` (миграция 001). Подпись области хранится в правиле. «Та же деталь» — по `name_key`, как в сводке. Фото (до 8, обычно 2–4 с одним общим комментарием): карточка показывает их крупной сеткой (2 и 4 фото — по два в ряд, 3 — в ряд; в узкой панели по два), клик открывает окно просмотра (`PhotoDialog`: колесо — зум к курсору, сдвиг мышью, двойной клик — вписать, листание между фото правила). Хранится уменьшенная копия (до 1600) и миниатюра 640 (`_t.jpg`) в `rules.dir` (пока `var/rules`, TODO `OPEN_ITEMS` №12), пути в базе относительные; сбой записи — файлы удаляются. «Прочитано» — строка в `rule_reads` на пару правило+пользователь; своё правило автор уже прочитал. Счётчик непрочитанных — `Feature.badge()` на вкладке; база перечитывается раз в `rules.refresh_s` (60), при показе вкладки и при открытии папки. Панель «Правила к детали» в `compare.right` (порядок 20) показывает правила не общие и относящиеся к детали открытой папки; без них скрыта. Сервис `rules`: `for_part(part_id, user_id=None)`, `unread_count(user_id=None)` — не из GUI-потока. Вставка фото из буфера и адресаты — функция `comments` (7.2).

Дашборд (`dashboard`, 9.1): своих таблиц и событий нет, ничего не публикует. Читает сервисы ядра `parts` и `folders.activity(since, until)` (завершённые папки с числом фото и отметки замечаний за период; граница «по» не включается) и, если есть, `type_db.search` для новых типов. Период — календарные неделя (с понедельника) / месяц / год, фильтр по виду проекта (из `project_kinds`). «Фото» — все фото завершённых за период папок (число просмотров программа не пишет). «Без проблем» — детали с завершённой проверкой за 90 суток и без замечаний за них. Столбики рисует `QPainter` (`charts.BarChart`, цвета из темы). Обновляется при показе вкладки и по событиям `folder.done`, `photo.marked`, `type.added/archived/restored`, если вкладка открыта.

Кнопки «Дефект» нет, миграция ядра 004 перевела старые дефекты в замечания; значение `defect` база ещё принимает, карточка «тип или дефект» в `type_db` — отдельная вещь и осталась. `mark_photo`: `sn=None` — не менять, `""` — стереть; `defect_kind` хранится у замечания (и `defect`), отметка типа его стирает. Запись идёт в фоне одной очередью, на экране отметка появляется после подтверждения базы. `photos.defect_kind` — миграция ядра 002.

## Слоты оболочки (поддерживать актуальным)

API окна, `ctx.shell`: `add_panel(слот, widget, key=None, order=0)` (тот же `key` заменяет панель), `remove_panel`, `register_slot(имя, layout)`,
`set_context(kind, project, device, part, path)`, `show_message(текст)`, `refresh_badges()`. Панель можно добавить раньше слота — дождётся его.
Нет слота (владелец отключён) — панель молча не показывается.

| Слот | Владелец | Что кладут |
|---|---|---|
| `shell.user` | оболочка | тег пользователя (`login`) |
| `shell.online` | оболочка | «кто онлайн» (`presence`) |
| `login.summary` | login | «С вашего последнего входа» (правила, комментарии, папки) — только на время диалога |
| `login.aside` | login | «Сейчас в работе», последние папки — только на время диалога |
| `compare.left` | compare | панель папок (`folders`). Колонка 240–280 px, пустая не занимает места |
| `compare.right` | compare | сводка по детали (`findings`), правила (`rules`). Колонка 280–320 px, пустая не занимает места |
| `compare.toolbar` | compare | кнопки во втором ряду панели инструментов (`annotate_tools`, `type_db`). Кнопкам — `setFocusPolicy(Qt.NoFocus)`, иначе стрелки и пробел достанутся им |

Окна «Сравнения» (`compare`, 03.11.2026): эталона по умолчанию нет — `CompareModel.reference` пуст, пока его не задали (`set_reference`, `set_reference_folder`, «Найти такую же деталь»). `reference_window` — эталон есть и окон больше одного; тогда текущих окон `count − 1`, иначе `count` (до 4, `MAX_CURRENTS = 4`). Текущее окно N — `views[(N + 1) % 4]`: при появлении эталона в `views[0]` окна 1–3 остаются теми же виджетами и не перечитывают фото. «Мигалка» — только при заданном эталоне.

Режим «Ракурсы» (`compare`): чистая логика — `features/compare/angles.py`, новых событий и сервисов нет. Кнопки ракурсов: `AnglesPlan.available` — все ракурсы папки, `views` — включённые (не больше 4), `AnglesModel.set_view_shown(view, on)` / `show_all()`; при входе в режим включаются все, на время работы, без записи. При листании `photo.changed` публикуется для фото активного окна; у SN нет этого ракурса — не публикуется. `compare.set_reference*` возвращает в режим «Сравнение»: эталона в «Ракурсах» нет.

Поворот (`compare`): при открытии папки фоновый поток читает заголовки файлов (`shared/viewer/decode.read_size`, с EXIF); пока не прочитано, нажатый поворот ждёт и применяется сам. Поворачиваются фото того же ракурса, у которых вертикальность на экране совпадает с текущим, каждое на свой шаг (`logic.turn_angle`); У чужой папки эталона размеры не читаются: её ракурс поворачивается целиком, только в памяти. Файл и кэш не меняются, `PhotoView` поворачивает только отрисовку. `photos.rotation` — миграция ядра 003, 0/90/180/270 по часовой стрелке. Клавиши — `data/hotkeys.json` → `compare.rotate_left/rotate_right`. Поворот действует на весь ракурс папки (номер из имени файла; имя не разобрано — только это фото), весь ракурс получает один и тот же поворот. Поворот, «Синхронно» включена — все окна вместе, у каждого весь его ракурс (фото, стоящие на экране так же, как в окне); выключена — **одно фото** активного окна; Shift + клавиша (или кнопка) — весь ракурс активного окна, остальные окна не трогаются. «Синхронно» есть в обоих режимах и запоминается для каждого своя (в «Сравнении» по умолчанию включена, в «Ракурсах» — выключена), доступна и при одном окне: без неё не повернуть одно фото. Фото текущей папки записываются в базу, эталон — только в памяти (до новой папки или нового эталона). В «Ракурсах» сетка не меняется. Повороту одного фото размеры файлов не нужны: он не ждёт их чтения. Запись — в фоне, в одной очереди с отметками; новых событий нет. Аннотации (4.1) хранить в координатах неповёрнутого фото.

Кнопки «Ракурс N» у найденного эталона (`compare`): эталон — первое фото ракурса, текущие окна — фото ракурса с тем же артикулом и SN, иначе первое фото ракурса; нет ракурса в папке — окна не меняются, в панели отметок предупреждение.

Настройки `compare` в `config/app.json`: `compare.neighbor_search_year_only` (true — соседние проекты за текущий календарный год), `compare.neighbor_search_days` (если год выключен и число больше 0 — последние N суток; иначе без ограничения). «Соседние проекты» — проекты того же вида (`projects.kind`), кроме своего.

Настройки `folders` в `config/*.json`: `folders.refresh_s` (60), `folders.done_days` (7), `folders.limit` (50). События `folder.copied`, `folder.opened`, `folder.done`, `photo.marked` обновляют панель сразу, остальные изменения — по таймеру.

Разметка (`annotate_tools`, `shared/annotate`): фигуры хранятся в долях **неповёрнутого** фото (0…1 по ширине и высоте исходника), ключ — путь фото, поэтому поворот, зум, уровень картинки и размер окна их не двигают. `Crop` («ножницы», на фото одна, новая заменяет старую), `Ellipse`, `Label` (левый верхний угол текста, остаётся горизонтальным при повороте). `History` — неизменяемые состояния, до 100 шагов на фото. Толщина линии и размер подписи — доли меньшей стороны фото, `paint_shapes(painter, shapes, mapper, colors)` годится и для сохранения фото с обводкой (4.2): отличается только `mapper` (`point(x, y)`, `unit`). Слой `AnnotationOverlay` цепляется к `PhotoView.set_overlay`: без выбранного инструмента мышь не перехватывает; с инструментом левая кнопка рисует, Shift+левая или средняя — сдвиг, двойной клик «вписать» не делает, колесо зумит как обычно. Клавиши отмены и повтора — `data/hotkeys.json` → `annotate`. Фигуры не пишутся ни в базу, ни на диск: это шаг 4.2.

Карточка «В базу» (`type_db`, 4.2): кнопка берёт фото активного окна `compare` (оно должно лежать в открытой папке) и его фигуры из сервиса `annotations`, без него сохраняет просто фото. Окно: деталь (только чтение), тип/дефект, номер типа (фото отмечено «Тип N» — N, иначе следующий за существующими у детали; отметку берёт из `compare.active_photo()`), отличие (необязательно с 03.11.2026: «Сохранить» доступна сразу; в базу — пустая строка, на карточке «—»), артикул (по умолчанию артикул детали). Сохраняется снимок на момент нажатия. Картинки: `<type_db.dir>/<вид>/<проект>/<устройство>/<деталь>/<Тип N>_<дата>_<время>_<случайные 6 знаков>_photo.jpg` (всё фото, фигуры нарисованы, «ножницы» не рисуются и не затемняют) и `_crop.jpg` (только если выделена область «ножницами»); оба повёрнуты как на экране, фото не больше `type_db.max_side` (2600) по длинной стороне. Сначала файлы, потом строка в `types`; сбой записи или базы — файлы удаляются. Пути в базе — относительные, через «/». Папку `type_db.dir` создаёт программа только если она относительная (локальная); абсолютную (сетевую) — нет. Таблица `types`: `part_id, kind (type|defect), type_no, description, article, photo_rel, crop_rel, source_photo, source_sn, created_by, created_at`; миграция 002 (4.3) добавила `archived_at, archived_by` — у живых записей пусто, заполнять и снимать будет 4.4. Настройки `type_db.dir` (пока `var/type_db`, TODO `OPEN_ITEMS` №12), `type_db.max_side`, `type_db.jpeg_quality`.

Вкладка «База типов» (`type_db`, 4.3): поиск по названию детали, артикулу, устройству, проекту, описанию и подписи «Тип N»; регистр, «е/ё» и разделители не важны («xs 2280» найдёт «XS-2280»), запрос подходит, если встречается подряд целиком или все его слова встречаются где-нибудь («тип 1» — одно слово, а не «тип» и «1»). Автор и дата в поиск не входят. Выдача: живые записи, потом архив, внутри групп новые первыми — это делает `logic.select`, а не вид. Все записи читаются в фоне целиком (сотни строк) и фильтруются в памяти на каждое нажатие клавиши, поэтому «мгновенно». Показывается не больше 60 карточек (дальше — «Показано N из M, уточните запрос»). Фильтры: «Все проекты» / виды проектов (из `parts.kinds`) / «Устройство: …» (появляется при выбранной карточке). Карточка справа: фото, вырезка, тип, статус, отличие, артикул, автор и дата, все типы устройства с пометкой «(архив)». Картинки — из общего `image_cache` (уровень L1, фоновое чтение). Обновление: при открытии вкладки (записи коллег), по событию `type.added`; одинаковые данные сетку не перестраивают. Прочитать не удалось — остаются прежние карточки и сообщение.

«БД» (`type_db`, 04.11.2026): вкладка называется «БД», внутри — «База типов» (по умолчанию) и «Замечания». «Замечания» — своей таблицы нет: все отметки фото «Замечание» (и старые «Дефект») из «Сравнения» через `folders.problem_marks` по всем деталям, фото — из папки проверки; плюс карточки «дефект», сохранённые через «+ В базу»; новые первыми. С запросом вкладки прячутся и поиск идёт по обеим базам (`logic.select_db`): типы, архивные типы, потом замечания по дате; у замечания ищутся деталь, артикул, устройство, проект, SN и вид. Карточка типа показывает вырезку, если она есть, иначе всё фото. Крестик на карточке — удалить запись насовсем (с подтверждением): строка из `types`, затем её картинки (не удалось стереть файл — остаётся, база уже чиста); событие `type.deleted`. Номер удалённого типа освобождается. Карточка замечания не выбирается и не удаляется (это отметка фото — снять её можно в «Сравнении»); поворот фото на ней не учитывается.

«+ Добавить из файла…» (`type_db/manual.py`, 04.11.2026): старые фото типов вручную, без «Сравнения» — фото с диска, вид проекта, проект, «в составе техники» (пусто — «Без устройства»), деталь, модель, номер типа, отличие (необязательно), дата карточки и кто добавил (обязательно). Деталь — `parts.ensure`, запись — тот же `TypeStore.save` без фигур (`SaveRequest.created_at` — дата карточки). Окно остаётся открытым, поля сохраняются: следующее фото той же детали — только файл. Подсказки проектов, устройств и деталей — из уже загруженной выдачи, список людей — вместе с ней, окно в базу само не ходит.

Большое фото (`type_db`): двойной клик по фото карточки или панели открывает `photo_window.PhotoWindow` на общем `PhotoView`: колесо, сдвиг мышью, двойной клик — вписать.

Архив (`type_db`, 4.4): кнопка на каждой карточке («В архив» / «Вернуть из архива»). Запись в базу идёт в фоне (`types.archived_at`, `archived_by`; повторное «в архив» время не меняет), и только после ответа базы карточка играет анимацию (`shared/widgets/stamp.py`, кадры считаются от времени без Qt): фото за 0,9 с становится серым и темнее, с 0,45 с печать «В АРХИВЕ» падает (масштаб 2,6 → 0,9 → 1, поворот −24° → −12° → −14°), на 1,0 с карточка «ударяет» вниз на 3 px; всего 1,25 с. Возврат — цвет за 0,9 с, печать тает. В конце сетка перестраивается: архивная уходит вниз. Данные, пришедшие во время анимации, применяются после неё. Анимацию можно выключить: `ui.animations` в `config/app.json` (тогда карточка сразу занимает место). События `type.archived` / `type.restored` — `{type_id, part_id}`. Архивное не служит эталоном: `types_for_part` по умолчанию его не отдаёт, номер архивного типа остаётся занятым (новый тип не получит тот же номер). Ограничений на то, кто может архивировать, нет.

Сводка по детали (`findings`, 5.1): панель в `compare.right`, собирается при `folder.opened` и при `type.added/archived/restored`, `folder.done`; в фоне, устаревший ответ (открыли другую деталь) отбрасывается; не получилось прочитать — остаётся прежняя сводка с пометкой. Своих таблиц нет: дефекты и замечания — отметки фото из сервиса `folders` (`problem_marks`), типы — из сервиса `type_db` (нет его — блок «Типы» скрыт). Идущая проверка (папка, которую открыли) в сводку не входит. **«Та же деталь» — только по точному названию** (регистр, «е/ё» и разделители не важны, как в `parts.find`), в любых устройствах и проектах. Похожие и более длинные названия («XS-2280» и «XS-2280 512GB») — другие детали: названия бывают неполными, нечёткое сравнение смешивало бы истории разных деталей. Типы одного номера у разных деталей с одним названием сливаются в строку: название — самой свежей записи, дата — самой ранней. Показывается `findings.list_limit` (10) свежих дефектов и замечаний, остальные — «Показано N из M».

«Ранее были замечания» (`findings`, 5.2): если за последние `findings.problem_days` (180) суток по детали отмечено не меньше `findings.problem_min_marks` (1) замечаний — `Summary.problem` не пуст. Считаются **все** отметки «замечание» и «дефект» (дефект — тоже замечание, для простоты). В панели над списками красная плашка («3 замечания за 180 дней · последнее 14.10», последняя проверка), а при открытии папки в строке состояния оболочки на 15 с появляется уведомление «… Будьте внимательнее.» (один раз на открытие, не на каждое обновление сводки). Идущая проверка не считается. События не публикуются.

Комментарии (`comments`, 7.2): таблицы `comments`, `comment_photos`, `comment_done` (миграция 001). Сообщение: текст, до 4 фото (кнопка «Фото» или Ctrl+V — картинка из буфера не вставляется в текст, а прикладывается; число фото и сроки жизни — `data/comments.json`: 7 / 1 / 30 дней / не удалять, считается в `expires_at`), адресат (всем или человек), привязка к открытой детали (`part_id`, `folder_id`, подпись `part_label` хранится в сообщении), пометка «ошибка ранее». Видно автору, адресату и всем при «всем»; «Готово» — строка в `comment_done` на пару сообщение+пользователь, убирает сообщение из списка и счётчика только у нажавшего; у своих сообщений «Готово» и «Ответить» нет. «Ответить» подставляет адресата (автор) и, если открыта та же папка, привязку. «Открыть в сравнении» — сервис `compare.open_folder`, кнопка только если `compare` есть. Счётчик на вкладке — `Feature.badge()`: чужие, не закрытые, не истёкшие. Истёкшие скрываются сразу, а из базы вместе с файлами фото удаляются при первом чтении после запуска. Фото — в `comments.dir` (пока `var/comments`, TODO `OPEN_ITEMS` №12): копия до 1600 и миниатюра 480 (`_t.jpg`); сбой записи — файлы удаляются. Обновление раз в `comments.refresh_s` (30), при показе вкладки и открытии папки. Сервис `comments`: `pending_count(user_id=None)` — не из GUI-потока.

Отчёт (`report`, 8.2): без своих таблиц и вкладки; кладёт панель в слот `draft.actions` (нет сервиса `draft` — панели нет): предпросмотр письма, «Записать в Excel», «Открыть в Outlook как ответ». **Excel**: колонки и название листа — `templates/excel_columns.json` (ключи `date, project, device, part, kind, type_no, sn, photos, kind_text, text, user`; нет файла — встроенный набор), строки — из `draft.snapshot`; файл `.xlsx` пишется без сторонних библиотек (`report/xlsx.py`) в `report.excel_dir` (пока `var/reports`) как `деталь_дата_время.xlsx` — старые не перезаписываются — и открывается в Excel. **Письмо**: `templates/mail_reply.html` (подстановки `${part} ${device} ${project} ${date} ${photos_total} ${types_line} ${defects_block} ${remarks_block} ${notes_block} ${user}`, значения экранируются; HTML-комментарии в шаблоне вырезаются), тема — настройка `report.subject` (`RE: ${part}, ${date}`). Outlook только открывает письмо (`Display`), отправлять нельзя; на Windows — `outlook_win.py`: 32-разрядный `cscript` (SysWOW64) со скриптом VBS, тема и текст передаются файлами UTF-8 в `report.work_dir` (`var/report`), pywin32 не нужен — так 64-разрядная программа достаёт 32-разрядный Outlook; на macOS — `outlook_fake.py` кладёт письмо в `last_mail.html`. После успешного открытия папка получает статус «готово» и событие `folder.done`; сбой — статус не меняется, причина в строке состояния. **Письмо пока новое, а не ответ на исходное**: связи папки с письмом нет (6.1). Временные данные — шаблон письма и колонки Excel (`OPEN_ITEMS` №4, №5, помечены TODO).

Кнопка «Добавить папку…» (`add_folder`): окно со строкой пути (можно вставить, в том числе в кавычках, UNC и кириллицу) и кнопкой «Обзор…»; фото ищутся в фоне (`shared/fs/photos.py`, .jpg/.jpeg, подпапки тоже), кнопка «Добавить» включается, когда фото найдены и поля верны. Подсказка по пути (`logic.suggest`): дата — из последней папки, если дата стоит в начале или в конце её названия («31.10.2026 (120 фото)»); деталь — папка перед ней; при 4 уровнях после диска (`Однотипность/Проект/Устройство/Деталь`) берутся проект и устройство, при 3 — устройство «Без устройства» (`data/add_folder.json`); вид проекта — по букве диска, если она совпала с видом. Это только подсказка: поля правятся, а написанное человеком подсказка не затирает. Запись — сервисы `parts.ensure` и `folders.add` + `add_photos` в фоне; повторное добавление того же пути ничего не дублирует (дописывает новые фото, сообщение «уже была в базе»). После записи публикуется `folder.copied` и папка открывается через сервис `compare`. Папка только читается. Это же делает ключ `atlas.exe --addfolder` (`atlas/addfolder.py`) без окна.

Черновик (`draft`, 8.1): таблицы `draft_notes` (заметки: папка + пользователь, у каждого свои), `draft_items` (строки, добавленные вручную: тип / дефект / замечание, SN, описание — общие у папки), `draft_comments` (пояснение к автоматической строке; ключ `photo:<id>` или `type:<N>`), миграция 001. Работает для открытой папки (`folder.opened`). Заметки автосохраняются через 1 с после паузы в наборе, при уходе с вкладки и при смене папки (запись в фоне, «Сохраняю… / Сохранено»). Автосписок строится из отметок фото папки (сервис `folders`): типы — одной строкой с числом фото, дефекты и замечания — по фото (SN, вид замечания); перечитывается по `photo.marked`, `folder.sorted` и при показе вкладки. Сервис `draft`: `snapshot(folder_id, user_id=None)` → `.notes`, `.entries` — для Excel и письма (8.2), не из GUI-потока. Слот `draft.actions` (создаёт `draft`, колонка «Действия» справа) — сюда `report` (8.2) кладёт «Записать в Excel» и «Открыть в Outlook как ответ». Миниатюры строк не входили. После сохранения пояснений и ручных строк публикуется `draft.changed`.

Установка и обновление (`core/release.py`, `publish.py`, `updater`, 10.1). Папка на сетевом диске, путь нигде не записан: программа выводит его из своего расположения.

```
<папка установки>\
  Atlas.bat, create_shortcut.vbs     запуск версии из version.txt; ярлык на рабочем столе, без прав администратора
  config\local.json, var\, logs\     настройки и данные, не зависят от версии
  release\version.txt                действующая версия: одна строка
  release\<версия>\atlas.exe, config\app.json, data\, templates\   у каждой версии своя папка
```

**Почему папки рядом, а не замена файлов:** файлы работающей программы заняты, у коллеги их не заменить; копирование поверх оставило бы смесь версий при обрыве сети. Если программа лежит в `release\<версия>`, задан `AppPaths.installed_home`: относительные пути настроек (`var/...`) и `logs` идут от папки установки, `local.json` читается оттуда же, `app.json`, `features.json`, `data`, `templates` — из папки версии. Тема и панели (`ui_state.json`) — в `%LOCALAPPDATA%\Atlas`, у каждого свои. Обычная копия (не в `release`) работает как раньше: всё в одной папке, `updater` молчит.

Выпуск: `publish.bat` из распакованной сборки (`atlas.exe --publish <папка>`): копия в `<версия>.part` → сверка sha256 → переименование → `Atlas.bat` и VBS → последним `version.txt`. Сбой при копировании, сверке или переименовании оставляет действующую версию. Более старую опубликовать нельзя. Настройки и данные установки не трогает, старые версии не удаляет: в них могут работать люди. Откат — вписать прежнюю версию в `version.txt`; `updater` предлагает любую версию, отличную от своей. **Откат после новой миграции базы не работает:** старая версия откажет функции с «базой новее». Правки `data/`, `templates/`, `features.json` в папке версии в следующую версию не переходят: их место — репозиторий. Версия одна — `atlas.__version__`; CI ставит `0.10.<номер сборки>` (`scripts/set_version.py`).

Запуск новой версии — прямо `atlas.exe` с `PYINSTALLER_RESET_ENVIRONMENT=1`, отдельным процессом. Сверка — в потоке-демоне, вопрос — когда окно открыто и нет другого диалога. Проверка только при старте: кто не закрывает программу, узнает при следующем запуске. Настроек нет, новых событий и сервисов нет.

## Картинки 3456×5184, 5–15 МБ

Одно фото в памяти целиком ≈ 72 МБ (RGBA). Поэтому — уровни:

| Уровень | Размер | Как получаем | Где храним |
|---|---|---|---|
| L0 миниатюра | ~160 px | из L1, без второго чтения исходника | диск: локальный кэш + память |
| L1 превью | 1/4 (864×1296, ~4,5 МБ) | JPEG DCT-масштабирование (быстро) | диск + память |
| L2 половина | 1/2 (~18 МБ) | там же | память, текущее ±1 |
| L3 полное | ~72 МБ | полное декодирование | память, только текущее (±1 при сильном зуме) |

- Листание: сразу L1, через 100–300 мс после остановки — L2/L3 для видимой области. Если окно увеличено (L1 размыт), следующее по ходу листания фото экран сравнения заранее готовит в нужном уровне (`PhotoView.needed_level`, приоритет «сосед»), а `set_photo` показывает готовый чёткий уровень сразу, минуя L1.
- После копирования папки — фоновый «прогрев» L0/L1 на локальный диск (`%LOCALAPPDATA%\Atlas\cache`, ключ: путь+размер+mtime).
- `get` отдаёт лучшее из памяти сразу (точный уровень, иначе выше, иначе ниже) и при необходимости ставит запрос в очередь: текущее > соседи > прогрев; внутри приоритета новые первыми; прогрев не занимает последний поток.
- Лимит памяти (`image_cache` в `config/app.json`), по объёму RAM целевой машины (из `docs/TARGET_MACHINE.md`). Нужен 64-битный Python.
- `setAutoTransform(True)` — учитывать EXIF-поворот.
- Синхронизация — в **нормализованных** координатах (доли ширины/высоты), чтобы фото разного размера смотрели в одно место. Доли считаются по экрану, то есть по повёрнутому фото.
- `PhotoView(cache)`: `set_photo(path, rotation=0)` — сохранённый поворот фото, место на экране не меняется, `set_rotation(rotation)` — человек повернул: точка в центре остаётся в центре, `rotation`, `clear()`, `fit()`, `zoom_by(factor)`, `state()` → (зум, cx, cy), `set_state(...)`, `set_overlay(слой)`, `photo_to_widget(x, y)` / `widget_to_photo(pos)` — доли неповёрнутого фото ↔ пиксели окна, `photo_unit`, `inner_rect()`, `refresh_cursor()`, `is_current_shown`, `shown_level`; сигналы `view_changed` (только от пользователя), `photo_shown`, `photo_failed`. Обычный `QWidget`, без `QGraphicsView`. Также `set_caption(tag, text, reference)`, `request_again()`, `shown_image_size` (с учётом поворота), `show_missing(текст)` — пустое окно с подписью, зум и место сохраняются. Свойство Qt `active` — подсветка активного окна.
- `Filmstrip(cache, colors)`: `set_items([FilmItem(path, mark_color, rotation)])`, `set_current(index)`, `set_mark(index, color)`, `set_rotations([поворот по порядку])`, `set_portrait(bool)`, `request_visible()`, `visible()`; сигнал `clicked(index)`. Рисует только то, что помещается. `set_current` ничего не запрашивает: миниатюры просит владелец после остановки листания.
- `SyncGroup(cache)`: `add(view, reference=False)`, `remove(view)`, `set_reference(view)`, `set_enabled(bool)`, `set_state(zoom, cx, cy)`, `fit()`, `zoom_by(factor)`, `rotate(delta, [(view, поворот)])` — все окна вместе, `show_photo(view, path, rotation=0)`, `show_photos([(view, path, rotation)])` — несколько окон за одну отмену очереди (листание «Ракурсов»), `touch(view)`, `active_current()`, `views`, `currents`, `reference`, `state`, `offsets` / `set_offsets(...)` / `reset_offsets()`; сигнал `changed(зум, cx, cy)`. **Включение синхронности не выравнивает окна** (04.11.2026): `set_enabled(True)` запоминает смещение каждого окна от того, которого касались последним (во сколько раз крупнее, на сколько сдвинут центр), и дальше окна двигаются вместе с этой подгонкой, в том числе при листании и повороте. «Сбросить» (`fit`) подгонку снимает, новая папка — тоже. У режимов «Сравнение» и «Ракурсы» подгонка своя. `cancel_pending()` вызывает только группа в `show_photo`: кэш общий, отмена из одного окна сбросила бы запросы других, поэтому после неё все окна повторяют запросы. Демо: `python tools/viewer_demo.py [папка]`.

## Как добавить / изменить / удалить функцию
- **Добавить:** `/new-feature id: описание` — шаблон папки, `FEATURE`, миграция, тест, строка в `features.json`, строки в таблицах выше.
- **Изменить:** `/change-feature id: что` — правится только папка функции (+ `data/`, `templates/`). Если меняется
  событие или сервис — сохранить старое поле/метод или обновить всех подписчиков и таблицу.
- **Удалить:** `/remove-feature id` — убрать из `features.json`, прогнать тесты независимости, удалить папку и строки в таблицах.
  Таблицы в БД остаются (безопасно), удаляются отдельной миграцией ядра только по просьбе.
