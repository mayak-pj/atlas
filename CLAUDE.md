# Atlas — правила для агента

## Перед любой работой
1. Прочитай `PROGRESS.md` (где мы), нужный раздел `PLAN.md`, `docs/ARCHITECTURE.md`.
2. Если шаг касается UI — `docs/UI_SPEC.md` и соответствующий файл в `design/mockup/`.
3. Если шаг касается запуска/сборки/тестов на Windows — `docs/TARGET_MACHINE.md`.
   **Не перепроверяй то, что там отмечено как «уже проверено»** — используй готовые решения из ваших прошлых проектов.

## Платформы
- Разработка: macOS. Цель: Windows 7 SP1 (точные данные — `docs/TARGET_MACHINE.md`).
- **Python 3.8** (на целевой машине 3.8.10 x64). Запрещено то, чего нет в 3.8: `match`, `list[str]`/`dict[...]`
  в аннотациях без `from __future__ import annotations`, `str.removeprefix/removesuffix`, `dict | dict`,
  `zoneinfo`, `functools.cache`, `asyncio.to_thread`, параметр `strict=` у `zip`.
  Проверка: `vermin --target=3.8- --no-tips --violations atlas/ tests/ samples/`.
- **PyQt5 5.15.10** (Qt 5.15.2 на Windows; на Mac — PyQt5-Qt5 5.15.19). Никакого Qt6 и PySide2.
- Пути Qt — только от пакета PyQt5, никаких `QLibraryInfo`: иначе ломается запуск из папки с кириллицей.
  Эмодзи и символы вроде `✓` в интерфейсе нельзя — только SVG. Прав администратора на цели нет: только portable-папка.
- Пути — `pathlib`, UNC (`\\server\share`) и кириллица должны работать. Никаких захардкоженных путей — только конфиг.
- Windows-only код (pywin32, COM) — только в `*_win.py`, импорт внутри функций. На macOS работают `*_fake.py`.

## Архитектура — главное правило
Каждая функция программы — **отдельный модуль** в `atlas/features/<id>/`. Подробно — `docs/ARCHITECTURE.md`.
- Функция импортирует только `atlas.core` и `atlas.shared`. **Никогда** — другую функцию.
- Связь между функциями — только события (`ctx.bus`) и сервисы (`ctx.services`), с проверкой, что сервис есть.
- Включение/выключение/порядок вкладок — `config/features.json`.
- Списки, тексты писем, справочники, горячие клавиши, цвета — в `data/` и `templates/`, не в коде.
- Тест `tests/test_boundaries.py` (запрет импортов между функциями) и `tests/test_features_independent.py`
  (приложение стартует с выключенной любой функцией) должны проходить всегда.
- Новое событие или сервис — сразу в таблицу в `docs/ARCHITECTURE.md`.

## UI
- Внешний вид — по `design/mockup/` и `atlas/core/theme/atlas.qss`. Цвета — только через токены темы.
- Тяжёлое (декодирование фото, копирование, БД, Outlook) — не в GUI-потоке.
- Текст интерфейса — на русском.

## БД
- Один файл SQLite на сетевом диске, 1–2 пользователя (иногда 3–4). Короткие транзакции, `busy_timeout`,
  ретрай при `database is locked`, режим журнала `DELETE` (WAL на сетевом диске нельзя).
- Схема — только через миграции функции (`features/<id>/migrations/NNN_*.sql`).

## Завершение каждого шага
1. `pytest` зелёный, `vermin` чистый.
2. Допиши в `PROGRESS.md`: дата, шаг, что сделано, решения, что осталось, известные проблемы.
3. Отметь шаг `[x]` в `PLAN.md`.
4. Предложи коммит (сообщение на русском) — коммить только по согласию.
5. Последними строками ответа:
   - **Чат:** можно очищать / 🛑 СТОП, не очищать — почему (знак 🛑 обязателен, когда очищать нельзя)
   - **Дальше:** номер и название следующего шага
   - **Модель:** Opus / Sonnet / Haiku — для следующего шага
   - **Без отчёта:** можно / нельзя переходить к следующему шагу, не дожидаясь отчёта с целевой машины — почему

## Что не должно попасть в репозиторий (он публичный)
- Настоящие названия двух видов проектов (аббревиатуры) — ни в код, ни в тесты, ни в документы, ни в макет, ни в данные.
  В репозитории они везде условные: `A` и `B`. Настоящие подписи — настройка `project_kinds` в `config/local.json` (не в git), см. `config/app.json`.
- Это проверяет `tests/test_no_private_names.py` (читает все файлы под git); он должен проходить всегда.
- Папку `my_reports/` публиковать нельзя: там отчёты с целевой машины, настоящие пути и сборка. Она в `.gitignore`; не добавлять её в git (в том числе через `git add -f`), не копировать оттуда файлы и их содержимое в репозиторий, артефакты и другие внешние сервисы.
