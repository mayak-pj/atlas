# Проверка «Качества» на Windows (шаг 12.5)

Зачем: на Mac три режима («OpenCV», «OpenCV NLM», «OpenCV Pro») работают быстро. Нужно узнать, как они работают на целевой
машине (Windows 7): входят ли OpenCV и NumPy в сборку, сколько секунд считает каждый режим, не зависает ли окно, хватает ли памяти.

**Этот файл закрывает только шаг 12.5.** Остальное, что накопилось с прошлого выезда, — в `docs/WIN7_CHECK.md` (см. раздел «Что ещё проверить за тот же выезд» ниже). Программа только читает фото, файлы не меняет.

**Фото `my_reports/` публиковать нельзя**: на флешку — можно, в облако, репозиторий и чаты — нет. После проверки удалить их с ПК.
Если Finder создал на флешке файлы `._…jpeg` — это служебные «двойники», программа их не показывает (с сборки после 14.11.2026).

**Версия в сборке** должна быть новее той, где появилась проверка `OpenCV и NumPy в сборке` в `reports\selfcheck.txt` (коммит «Качество: проверка в selfcheck»).
Если в `Artifacts` нет `atlas-win7-x64` — запуск ещё идёт или упал; тогда смотреть журнал запуска, на ПК ничего не везти.

## Подготовка (5 минут)
1. На целевом ПК: свойства `atlas-win7-x64.zip` → «Разблокировать» → распаковать **на локальный диск**, например `C:\AtlasTest\` (без прав администратора).
2. Записать данные ПК: процессор, ОЗУ, видеокарта (Win+Pause или `dxdiag`). Они нужны для оценки времени.
3. Фото скопировать на **локальный** диск, например `C:\AtlasTest\photos\` (скорость сети в этой проверке не нужна).

## Шаг 1. Библиотеки на месте (самое важное)
1. Запустить `check_win7.bat` (окно откроется и закроется само, ожидается код 0).
2. Открыть `reports\selfcheck.txt`, найти строки:
   - `ОК     OpenCV и NumPy в сборке`
   - `ОК     «Качество»: режим deblur (800×600 → 1600×1200): … с; OpenCV 4.5.5, NumPy 1.24.4`
   - то же для `max` и `pro`.
3. **Записать три времени.** Для ориентира: на Mac (Apple M) — 0,06 / 0,12 / 0,7 с.
4. Если `ОШИБКА … OpenCV и NumPy в сборке`: библиотеки не вошли. Дальше не идти, прислать `reports\selfcheck.txt` и папку `_internal` (есть ли в ней `cv2`).

Также записать размер распакованной папки (на сколько МБ выросла сборка; на CI размер виден в журнале шага `Check bundle for Windows 7`).

## Шаг 2. Внести фото
1. `atlas.exe` → «+ Добавить себя» → фамилия → «Войти».
2. Слева над списком «Добавить папку…» → путь `C:\AtlasTest\photos` (вставкой или «Обзор…») → подставятся поля, любые значения (вид A или B) → добавить.
3. Папка появится в списке «Новые» слева → щёлкнуть → открывается во вкладке «Сравнение».
   Один фото-ряд для проверки — это три разные фото: листать стрелками.

## Шаг 3. «Качество» на каждом фото и режиме
В строке кнопок функций «Сравнения»: **«Качество»** → открывается список «OpenCV», «OpenCV NLM», «OpenCV Pro» (рядом время). Выбор режима сразу включает улучшение; «Выключить» — убрать.

Для каждого из трёх фото и каждого режима:
1. Включить режим, при **общем виде** подождать (улучшенная картинка появляется через долю секунды после остановки).
2. Приблизить колесом до ≈ 3×, остановиться и подождать; потом ≈ 6×, потом ≈ 12×.
3. Смотреть на этих местах:
   - **плата целиком** — район процессора и микросхем;
   - **модуль памяти** — наклейка «Warranty Void If Removed» и «1.2 V» (размытая — главный случай);
   - **матрица** — маленькая плата справа: подписи `R408`, `R403`, `R401`, `CP402`.
4. Оценить глазами по каждой паре (фото × режим × зум), поставить в таблицу ниже:
   - **читаемость** подписей — хуже, как было, лучше, намного лучше;
   - **артефакты** — ореолы вокруг букв, «зебра» внутри букв, «бусинки» на штрихах, вымытые цвета;
   - **ложные детали**: если проявились штрихи, которых на исходном фото нет, — это недопустимо, записать, где.
5. **Время расчёта** брать не секундомером, а из `logs\atlas.log`: строки вида
   `Качество: режим pro, часть фото 600x400 → экран 1800x1200: 1.30 с`
   (если в конце «(без улучшения)» — режим не отработал или фото уже резкое; строка `Качество: режим … не отработал` с трассировкой — ошибка).

## Шаг 4. «До / после» (для показа)
- Включить любой режим → кнопка **«До / после»** рядом с «Качеством»: слева исходное фото, справа улучшенное, границу тянуть мышью за кружок со стрелками.
- Клавиша **Q**: пока держите — все окна показывают исходное фото.
- Снять 2–3 экрана (PrintScreen или «Ножницы») на «матрице» и «модуле памяти» с шторкой посередине. Они пригодятся для показа.

## Шаг 5. Нагрузка
1. Развернуть окно на весь экран, F11 (режим «Во весь экран»), включить «OpenCV Pro», приблизить ≈ 3×.
2. Открыть диспетчер задач (Ctrl+Shift+Esc), найти `atlas.exe`: записать **пик памяти** во время расчёта.
3. Записать, **зависает ли окно** во время расчёта (двигается ли мышь, реагируют ли кнопки, листание стрелками).
4. Листать стрелками с включённым «Pro» 10–20 фото подряд (если фото больше трёх): не тормозит ли, не растёт ли память.
5. Выключить «Качество»: окно возвращается к обычной работе сразу.
